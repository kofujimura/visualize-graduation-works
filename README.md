# 卒業研究エクスプローラー

研究室の卒業研究（タイトルと概要）を、LLM とテキスト埋め込みを使って 2 通りの方法で可視化する Web ページです。

- **類似度マップ** … 概要の意味の近さで研究を 2 次元に配置し、似ている研究同士を線で結んだネットワーク図
- **キーワードツリー** … 各研究に付けたキーワードを、概念の上位・下位関係で整理した木構造

2 つの表示は 1 つのページに統合されていて、相互に行き来できます。

- 類似度マップで研究を選ぶ → キーワードが表示され、押すとキーワードツリーでその語を開く
- キーワードツリーで研究を選ぶ → 「類似度マップでこの研究を見る」で、マップ上の位置と似ている研究を表示
- キーワードツリーで語を選ぶ → 下位の語を含めた該当研究を、類似度マップ上でまとめて強調

参考：[kofujimura/data-visualization-using-LLM](https://github.com/kofujimura/data-visualization-using-LLM)（食品データの類似度ネットワーク）

## 使い方（閲覧）

`index.html` をブラウザで開くだけです（サーバ不要、`file://` で動きます）。
D3.js を CDN から読み込むため、インターネット接続が必要です。

| 操作 | 類似度マップ | キーワードツリー |
|---|---|---|
| クリック | 研究の概要・キーワード・似ている研究を表示 | 語の上位・下位の枝と関連研究を表示 |
| マウスを重ねる | 類似度上位の研究とのつながりを強調 | 語と研究数を表示 |
| ドラッグ | 点を動かす（つながった研究も一緒に動く） | 画面を移動 |
| ホイール | 拡大縮小 | 拡大縮小 |

上部のコントロールでは、類似度マップの色分け（テーマ別／年度別）、年度の絞り込み、ツリーのレイアウト（横型／放射状）の切り替えと検索ができます。

URL の末尾に表示状態が入るので、そのまま共有やブックマークができます。

```
index.html#map&work=2026-04     類似度マップで研究 2026-04 を選んだ状態
index.html#tree&kw=NFT          キーワードツリーで「NFT」を選んだ状態
```

## 仕組み

```
各年度の資料（PDF・Web・Markdown）
   │  similarity-map/build.py
   ├─ テキスト収集 ───────────────→ cache/works_raw.json
   ├─ 要約（約250字にそろえる）─── gpt-5.4-mini ─→ cache/summaries.json
   ├─ 短縮ラベル（10字程度）───── gpt-5.4-mini ─→ cache/labels.json
   ├─ ベクトル化 ─────────────── text-embedding-3-large ─→ cache/embeddings.json
   ├─ コサイン類似度 → 各研究の上位3件を線で結ぶ
   ├─ K-means（8グループ）＋ グループ名 ── gpt-5.4-mini
   ├─ t-SNE で 2 次元の初期配置
   └─→ similarity-map/graph.json, graph.js
          │  keyword-tree/build.py
          ├─ 全研究に 3〜5 個のキーワード付与 ── gpt-5.5 ─→ cache/keywords.json
          ├─ 上位 → 下位の概念ツリーを作成 ─── gpt-5.5 ─→ cache/tree.json
          ├─ 検証・手動修正の適用・冗長な階層の格上げ
          └─→ keyword-tree/tree.json, tree.js
                 │
               index.html（両方の .js を読み込んで表示）
```

主な設計上の判断：

- **概要の長さをそろえる** … 要旨全文（約1,200字）と短い概要（約250字）が混在すると、内容より「文章の長さ・書き方」で年度ごとにまとまってしまいます。そのため、全件を約250字の概要に要約してからベクトル化しています。
- **長いタイトルは短縮ラベルで表示** … マップ上には LLM が付けた 10 字程度のラベルを表示し、正式タイトルはパネルやツールチップで表示します。
- **配置は t-SNE ＋ 力学モデル** … 力学モデルだけでは、テーマのまとまりが空間的に見えにくくなります。そこで t-SNE の座標を初期配置とし、ラベルが重ならないよう力学モデルで調整します。表示後は元の位置へ引き戻す力を弱めているので、点をドラッグして動かせます。
- **キーワードはまとめて付与** … 研究ごとに別々に付けると表記ゆれが起きるため、全件を 1 回のリクエストで渡し、研究をまたいで同じ語を使うよう指示しています。
- **上位の語は下位の語の研究を含む** … ツリーをたどって絞り込めるよう、上位の語を選ぶと下位の語に付いた研究も表示します（直接付いた研究と、下位の語から含まれる研究は分けて表示）。
- **冗長な階層の格上げ** … 1 件の研究にしか付いていない語で、親の語もその同じ研究 1 件にしか付いていない場合は、その語を 1 つ上の層へ移します。

## ファイル構成

```
index.html                     統合ページ（これを開く）
README.md
.env.local                     OPENAI_API_KEY=...（自分で作成・コミットしない）
similarity-map/
  build.py                     収集・要約・ラベル・埋め込み・クラスタリング・t-SNE
  labels_override.json         短縮ラベルの手動修正 {"研究ID": "ラベル"}
  cache/                       API の結果（再実行時は API を呼ばない）
  graph.json / graph.js        出力データ
  index.html                   類似度マップ単体のページ（統合前の版）
keyword-tree/
  build.py                     キーワード付与・ツリー作成・検証
  tree_override.json           ツリーの親の手動修正 {"語": "新しい親"}
  cache/
  tree.json / tree.js          出力データ
  index.html                   キーワードツリー単体のページ（統合前の版）
```

## 自分の研究室のデータで作る

### 1. 準備

- Python 3.10 以上
- `pip install openai numpy scikit-learn`
- OpenAI API キー。プロジェクト直下に `.env.local` を作って次のように書きます。

  ```
  OPENAI_API_KEY=sk-...
  ```

- （PDF から抽出する場合のみ）`pdftotext`（macOS なら `brew install poppler`）

### 2. 研究データを用意する

一番簡単なのは、収集処理を使わずに `similarity-map/cache/works_raw.json` を直接用意する方法です。
このファイルがあれば、`build.py` はテキストの収集をスキップします。

```json
[
  {"id": "2024-01", "year": 2024, "title": "研究タイトル", "fulltext": "要旨の全文 ..."},
  {"id": "2025-01", "year": 2025, "title": "研究タイトル", "summary": "約250字の概要 ..."}
]
```

- `id` … 一意な文字列（URL にも使われます）。`年度-連番` を推奨します。
- `summary` がある研究はそのまま使います。`fulltext` だけの研究は、LLM で約250字に要約します。
- 著者名は含めないことを推奨します（ページを共有する場合に備えて）。

収集処理を自分の資料に合わせて書き換える場合は、`similarity-map/build.py` の次の部分を編集してください。

| 箇所 | 内容 |
|---|---|
| `TITLES` | 要旨集 PDF のページ番号 → タイトル（PDF から抽出すると崩れるため手で指定） |
| `collect_pdf_years()` | 要旨集 PDF（1 ページ 1 件、「１．はじめに」以降を本文とする） |
| `collect_2025()` | Web 記事の `<li><strong>タイトル</strong><br>概要</li>` を抽出 |
| `collect_2026()` | Markdown の `### タイトル` と、それに続く本文を抽出 |

### 3. 生成する

```sh
set -a; . ./.env.local; set +a
python3 similarity-map/build.py     # 先に実行（keyword-tree が graph.json を使う）
python3 keyword-tree/build.py
```

`index.html` を開いて確認します。75 件程度であれば API の費用はわずかで、処理は数分で終わります。

### 4. 研究室に合わせて変える箇所

| ファイル | 箇所 | 内容 |
|---|---|---|
| `index.html` | `<h1>`、`<title>` | ページの見出し |
| `index.html` | `NEW_YEAR` | 太枠で強調する年度（最新年度など） |
| `index.html` | 年度の色（`yearColor` の `range`） | 年度の数に合わせて色を増減 |
| `similarity-map/build.py` | `N_CLUSTERS` | テーマのグループ数（目安：件数 ÷ 10 前後） |
| `similarity-map/build.py` | `TOP_K` | 各研究から線を引く類似研究の数 |
| `keyword-tree/build.py` | `ROOT_NAME` | ツリーの根の名前 |
| 両方の `build.py` | `CHAT_MODEL` / `MODEL` / `EMBED_MODEL` | 使用するモデル |

## 結果を修正する・作り直す

LLM の出力は実行のたびに変わるため、結果は `cache/` に保存し、再実行しても同じ結果になるようにしています。

- **一部だけ直す** … 手動修正ファイルに書いて `build.py` を再実行します。
  - 短縮ラベル：`similarity-map/labels_override.json`（例：`{"2022-09": "手振り360度撮影"}`）
  - ツリーの親子関係：`keyword-tree/tree_override.json`（例：`{"失効レジストリ": "ブロックチェーン"}`）
- **作り直す** … 該当する `cache/*.json` を削除して再実行します。
  - 研究を追加・変更した場合は `similarity-map/cache/` を全部削除し、続けて `keyword-tree/cache/` も削除します。
  - キーワードやツリーだけ作り直す場合は `keyword-tree/cache/` を削除します（`tree.json` だけ消すと、キーワードはそのままでツリーだけ作り直せます）。
  - グループ数を変えた場合は、グループ名のキャッシュ（`cluster_names_k{数}.json`）が自動で別ファイルになります。

`keyword-tree/build.py` は LLM が作ったツリーを検証し（全キーワードが 1 回ずつ現れるか、親が存在するか、循環がないか）、問題があれば補正して内容を表示します。

## このリポジトリに含めていないもの

- 要旨集・中間発表の PDF（元資料）
- `similarity-map/cache/works_raw.json`（PDF から抽出した要旨の本文）

要約・ラベル・埋め込み・キーワード・ツリーのキャッシュは含めているので、`index.html` はそのまま表示できます。
また、`keyword-tree/build.py` は API を呼ばずに再実行できます。
`similarity-map/build.py` を再実行するには `works_raw.json` が必要です。自分のデータで作る場合は、上の手順で用意してください。

## 注意

- 要約・短縮ラベル・キーワード・ツリーは LLM が生成したものです。公開する前に内容を確認してください（ページ上のパネルで各研究の概要とキーワードを確認できます）。
- 類似度マップの配置（t-SNE）とテーマ分け（K-means）は、乱数の種を固定しているため、同じデータなら毎回同じ結果になります。
- `.env.local` と API キーは、リポジトリに含めないでください。
